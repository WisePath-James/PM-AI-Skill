# 12 - 阶段收尾与经验教训

## 阶段收尾流程

每个阶段（或 Sprint）结束时，执行以下收尾流程：

```
1. 阶段产物验收确认 → 2. 文档归档 → 3. 经验教训收集 → 4. 阶段评审报告 → 5. 进入下一阶段授权
```

### Step 1：阶段产物验收确认

- 确认本阶段所有已标记为"已验收"的 REQ 确实满足验收标准
- 确认所有 WBS 项已关闭或有明确的延续计划
- 确认所有变更已记录并得到 Human Owner 确认
- 确认所有 QC 报告已存档

### Step 2：文档归档

更新以下文档：
- PM_STAGE_HISTORY.md（记录本阶段的摘要）
- LESSONS_LEARNED.md（记录本阶段的经验）
- PM_CURRENT_STATUS.md（更新为最新状态）
- 相关 Warm/Cold 层文档（版本更新）

### Step 3：经验教训收集

在阶段结束前，与 Human Owner 和 Coder 一起快速回顾：
- 什么做得好？（继续做）
- 什么做得不好？（改进）
- 什么需要停止做？（避免）
- 有没有新的风险或问题暴露出来？

### Step 5：进入下一阶段授权

PM AI 向 Human Owner 报告阶段结果，Human Owner 确认：
- 阶段产物验收
- 下一阶段授权
- 下一阶段计划和目标

## 最终交付收尾（项目结束时）

1. **最终验收**：Human Owner 对所有 REQ 做最终确认
2. **文档移交**：所有 PM 文档移交给 Human Owner（或存档）
3. **完成度终审**：PM AI 出具最终完成度报告
4. **关闭日志**：更新所有日志状态为"Closed"
5. **归档命名**：最终归档所有文档（添加"FINA L"标识）
6. **回顾会议**：与 Human Owner 进行项目回顾（如果时间允许）

## 项目提前终止

如果项目提前终止：
1. 记录终止原因到 PROJECT_BRIEF.md
2. 记录已完成的交付物和未完成的交付物
3. 归档所有文档
4. 记录经验教训（为什么要终止？从中学到什么？）
5. 向 Human Owner 提供终止报告

- [ ] 阶段评审报告已存档
- [ ] Human Owner 已批准进入下一阶段

### 项目最终收尾
- [ ] 所有 REQ 已验收

- [ ] Human Owner 已签署最终验收
