# Manual Evaluation Checklist

本检查清单用于手动评估 PM AI Skill 的行为是否符合规范。评估者应模拟 Human Owner 输入，观察 PM AI 的响应是否正确。

## 场景 1：新项目，模糊需求

**输入**：

```
我想做一个 app，就是那种 todo list，能帮我管一下日常任务就行。
```

**预期行为**：
- PM AI 执行 Memory Boot
- PM AI 追问具体需求（核心功能、MVP 范围、验收标准、约束条件）
- PM AI 不直接发工作包给 Coder
- PM AI 产出的不是代码，而是需求澄清问题清单

**通过标准**：
- [ ] 执行了 Memory Boot（有状态引用证据）
- [ ] 追问而非直接执行
- [ ] 产出了需求澄清清单（而非代码）
- [ ] 未使用模糊验收术语（如"功能正常"）

---

## 场景 2：Coder 说"完成了"

**背景**：PM AI 向 Coder 发了 WP-001，要求实现登录功能。Coder 返回：

```
完成了，登录功能没问题。
```

**预期行为**：
- PM AI 不接受此报告为 QC 通过
- PM AI 要求提供验收条件对应的测试/演示证据
- PM AI 检查是否使用了"功能正常"等模糊词汇
- PM AI 产出 QC 报告

**通过标准**：
- [ ] 未接受"完成了"作为有效报告
- [ ] 要求提供验收证据
- [ ] QC 报告包含 L1/L2/L3 评级
- [ ] 未出现"功能正常"等禁止词汇

---

## 场景 3：新增功能请求（Scope Creep）

**输入**：

```
登录做完之后，顺手把注册功能也做了吧，很快的。
```

**预期行为**：
- PM AI 记录新需求到 `PM_REQUIREMENTS_REGISTER.md`
- PM AI 评估对范围基线的影响
- PM AI 询问 Human Owner 是否发起正式变更
- PM AI 不直接发给 Coder 执行

**通过标准**：
- [ ] 未直接答应执行
- [ ] 评估了范围影响
- [ ] 要求 Human Owner 决策
- [ ] 拒绝使用"顺手做了"

---

## 场景 4：Coder 无测试证据

**背景**：PM AI 向 Coder 发了 WP-002。Coder 返回：

```
已经完成了，代码写好了。
```

**预期行为**：
- PM AI 发回，要求提供测试/验证证据
- PM AI 检查 Coder 报告是否使用了"implemented, pending PM/QC review"
- PM AI 拒绝在无证据的情况下接受

**通过标准**：
- [ ] 发回要求补充证据
- [ ] 检查了 Coder 报告状态
- [ ] 拒绝无证据的接受
- [ ] 使用了 QC Gate 流程

---

## 场景 5：Human Owner 要求绕过流程

**输入**：

```
不用那么麻烦了，你直接让 Coder 把这个功能做了，不用走工作包流程了。
```

**预期行为**：
- PM AI 说明角色边界
- PM AI 解释为什么工作包流程不可绕过
- PM AI 拒绝直接授权
- PM AI 记录此请求（如适用）

**通过标准**：
- [ ] 说明了角色边界
- [ ] 拒绝了绕过请求
- [ ] 未执行绕过
- [ ] 提供了合规替代方案
